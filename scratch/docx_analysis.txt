P3: 1. Executive Summary & Conceptual Mental Model
P4: UNIFIÉE is an end-to-end B2B operating platform engineered specifically for the Food and Beverage (F&B) packaging procurement lifecycle. It coordinates F&B Brands (cafés, cloud kitchens, QSRs), Packaging Designers (freelancers, prepress studios), and Packaging Manufacturers (converting plants, cup fabricators, printers).
P5: 
P6: The Core Problem: F&B packaging involves intricate mechanical parameters: paper grammage (GSM), corrugated flute thickness (E-flute for pizza boxes vs B-flute for shipping cartons), barrier liners (polyethylene vs aqueous water-based barriers), and die-cut tolerances. Miscommunication leads to costly prepress errors, wrong MOQs, and wasted manufacturing runs.
P7: The Solution Architecture: UNIFIÉE standardizes technical specification drafting with AI, enables hybrid vector retrieval for supplier matching, facilitates prepress dieline signoffs, and manages orders across a 6-stage lifecycle.

P10: 2. Platform Architecture: Connecting the Three Sides
P11: The core architectural innovation of UNIFIÉE is its ability to bridge three distinct marketplace personas into a unified transaction pipeline:
P12: F&B Businesses (Buyers): Post natural-language requirements, compare automated vendor quotes, browse pre-vetted designers, approve pre-press digital proofs, and track shipment milestones.
P13: Packaging Designers (Creators): List structural design services (dielines, label art, 3D mockups), utilize AI to write gigs and briefs, receive brand commissions, and deliver print-ready files directly to the order record.
P14: Packaging Manufacturers (Converters): Publish industrial product lines with tiered volume pricing, quote on inbound brand requirements, receive client-approved dielines, and advance factory fulfillment stages.

T5_R0_C0_P0: THE ANTI-DOUBLE-BILLING SAFEGUARD
Why Cryptographic Idempotency Matters in B2B Packaging:
In B2B commerce, an order can cost ₹50,000 or more. If a café manager on a poor Wi-Fi connection clicks 'Confirm Order', waits 5 seconds, gets anxious, and clicks 'Confirm Order' again, a poorly engineered platform would create duplicate purchase orders and place two separate manufacturing runs.

UNIFIÉE creates a unique cryptographic fingerprint (an SHA-256 hash) of the order data. If the server sees the exact same fingerprint while processing, it locks duplicate runs. If the request has already completed, the system replays the saved response directly from the database without re-executing any database writes.
T6_R0_C0_P0: // src/lib/server/idempotency-core.ts
function stableStringify(value: unknown): string {
    if (value === null || typeof value !== "object") return JSON.stringify(value)
    if (Array.isArray(value)) return `[${value.map(stableStringify).join(",")}]`
    const record = value as Record<string, unknown>
    return `{${Object.keys(record).sort().map((key) => `${JSON.stringify(key)}:${stableStringify(record[key])}`).join(",")}}`
}

export function hashIdempotencyPayload(payload: unknown): string {
    return crypto.createHash("sha256").update(stableStringify(payload)).digest("hex")
}
T7_R0_C0_P0: HYBRID SEARCH EXPLAINED SIMPLY
Why Traditional Search Fails in Industrial Packaging:
1. Keyword Search Fails: If a café searches for 'biodegradable takeout bowl', a standard search misses a factory listing titled 'Compostable Sugarcane Bagasse Bowl 500ml' because the words don't match.
2. Pure Vector AI Search Fails: Vector AI understands meaning, but struggles with numbers. When searching for an '8 oz coffee cup', pure vector search might return a '12 oz coffee cup' because both are coffee cups in latent space.

UNIFIÉE Hybrid Solution: We run BOTH vector search (for conceptual meaning) AND PostgreSQL full-text search (for exact numbers and sizes), then fuse them using Reciprocal Rank Fusion (RRF) so the best matches rise to the top, boosting exact matches alongside conceptual relevance.
T8_R0_C0_P0: // src/lib/ai/retrieval.ts
export async function searchHybrid({ query, session, filters, limit = 5 }) {
    const trimmed = query.trim();
    if (!trimmed) return [];
    assertRequirementAccess(session, filters?.entityType);

    const [queryVector, textResults] = await Promise.all([
        embedSingleQuery(trimmed),
        searchFullText({ query: trimmed, session, filters, limit }).catch(() => []),
    ]);

    let vectorResults = [];
    if (queryVector) {
        vectorResults = await searchVector({ queryVector, session, filters, limit }).catch(() => []);
    }

    if (vectorResults.length > 0 && textResults.length > 0) {
        return reciprocalRankFusion(vectorResults, textResults, limit);
    }
    return (vectorResults.length > 0 ? vectorResults : textResults).slice(0, limit);
}

export async function uploadProofAction(input: { orderId: string; fileUrl: string; note?: string }) {
    const vendor = await getAuthenticatedVendor()
    if (!vendor) return { success: false, error: "Unauthorized." }

    const [order] = await db.select({ id: businessOrdersTable.id, status: businessOrdersTable.status })
        .from(businessOrdersTable)
        .where(and(eq(businessOrdersTable.id, input.orderId), eq(businessOrdersTable.vendorId, vendor.manufacturerId)))
        .limit(1)

    if (!order || !canTransition(order.status as OrderStatus, "proof_pending", "manufacturer")) {
        return { success: false, error: "A proof can only be uploaded after the order is confirmed." }
    }

    const [latest] = await db.select({ version: orderArtworkProofsTable.version })
        .from(orderArtworkProofsTable)
        .where(eq(orderArtworkProofsTable.orderId, order.id))
        .orderBy(desc(orderArtworkProofsTable.version))
        .limit(1)

    await db.transaction(async (tx) => {
        await tx.insert(orderArtworkProofsTable).values({
            id: crypto.randomUUID(),
            orderId: order.id,
            version: (latest?.version ?? 0) + 1,
            fileUrl: input.fileUrl,
            uploadedBy: vendor.userId,
        })
        await tx.update(businessOrdersTable).set({ status: "proof_pending", updatedAt: new Date() })
            .where(eq(businessOrdersTable.id, order.id))
    })
    return { success: true }
}
